Lesson 0003 — RBAC: deny by default

Primary source: NIST SP 800-162 (RBAC).

Why this lesson

In your centres, a TL does not get access to a queue "by default" — access is granted explicitly per skill, per campaign, per data class. RBAC formalises that: permissions attach to roles, not people, and anything not explicitly granted is denied.

Concept

  • Role: a named set of permissions (e.g. sami, suby). Users are assigned roles.
  • Permission: an action on a resource (e.g. run the WFM engine on internal data).
  • Deny by default: a request with no matching permission is refused — never "allowed unless blocked".
  • Separation of duties: no single role holds conflicting permissions (e.g. propose + approve the same change).

Helix's nine role seats (SAMI, SUBY, PHILI, WILI, ANDY, NONO, MAYA, LIZA, TOMY) each own specific engines and data classifications with financial approval limits — a RoleSpec matrix, not ad-hoc grants.
