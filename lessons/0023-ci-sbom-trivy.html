Lesson 0023 — CI, SBOM and Trivy

Primary source: CycloneDX, Trivy, GitHub Actions docs.

Why this lesson

CI automates the checks you'd otherwise forget: tests, lint, type-check, image scan, SBOM generation. An SBOM (Software Bill of Materials) lists every dependency; Trivy scans images for known CVEs. Together they answer "what's in this build and is it safe?"

Concept

  • CI (GitHub Actions): workflows triggered on push/PR; run tests, lint, builds.
  • SBOM (CycloneDX): machine-readable list of components and versions in a build.
  • Trivy: vulnerability scanner for container images, filesystems, IaC.
  • Hash-verified runtime lock: Helix uses a runtime lock + CycloneDX SBOM + Trivy image scan in CI.

Helix's CI audits the API lock, uploads CycloneDX dependency + image SBOMs, runs a SHA-pinned Trivy image scan. The n8n platform's single remaining FAIL in verify.sh is the Trivy scan (Trivy not installed on host).
