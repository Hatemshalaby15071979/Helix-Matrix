Lesson 0011 — Local-first AI

Primary source: localfirstweb.dev + your portfolio's operating principles.

Why this lesson

Local-first means the app works on the user's own machine, makes no network calls in the evidence path, holds no credentials, and touches no production systems. For contact-centre data (PII, call recordings, SOPs), this is not a preference — it's a contract.

Concept

  • Offline by default: core function works with no network.
  • No product data egress: topics, lessons, scripts, audio never leave the machine. Network is limited to package/model installs.
  • Own your data: stored locally (SQLite, IndexedDB), exportable, no vendor lock-in.
  • Sync is optional and explicit: never silent; user-initiated.
  • Local models: Ollama on localhost; cloud models off by default, keys in OS keyring.

Your portfolio principle: "Cloud only when a customer's value justifies it." Helix, LIVE Support, Signoff, SigmaHelix OS, n8n platform — all local-first.
