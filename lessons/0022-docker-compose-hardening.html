Lesson 0022 — Docker and Compose hardening

Primary source: Docker Compose docs + CIS Docker Benchmark + n8n platform.

Why this lesson

Shipping a container is easy; shipping a safe container is not. Hardening means: non-root user, read-only root filesystem, dropped capabilities, bounded resources, no published DB ports, secrets via env files (never committed).

Concept

  • Non-root (UID 1000): container process runs as an unprivileged user.
  • Read-only root FS: read_only: true + a tiny writable /tmp.
  • Dropped capabilities: cap_drop: [ALL], add back only what's needed.
  • Bounded resources: CPU/mem limits per service.
  • Internal networks: DB only on an internal network, no published port.
  • Secrets: .env (mode 600), never committed; .env.template committed.
  • Image pinning: tags/digests, not :latest, in production.

n8n platform: n8n UID 1000 read-only root FS, dropped caps, bounded resources, 127.0.0.1:5678 only; Postgres internal-only; cloudflared no host ports; Ollama on host bridge 172.30.50.1:11434.
