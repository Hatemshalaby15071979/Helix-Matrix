Lesson 0021 — Data stack: Pandas, SQLite, PostgreSQL, Parquet

Primary source: Pandas docs, PostgreSQL docs, Parquet.

Why this lesson

Your tools move data: ingest, transform, store, query, export. Each tool in the stack has a job; using the wrong one (e.g. Postgres for a local single-file app) adds cost without value.

Concept

  • Pandas: in-memory tabular data; great for transforms, EDA, small-to-medium data. Not a database.
  • NumPy: numeric arrays; the foundation Pandas builds on.
  • SQLite: single-file relational DB, zero server, perfect for local-first apps (SigmaHelix OS uses one file).
  • PostgreSQL: client-server RDBMS with concurrency, transactions, rich types; for multi-user/multi-tenant.
  • Parquet: columnar file format; efficient storage + fast analytics reads; good for exports/archives.

Helix uses PostgreSQL + Parquet + SQLite across its engines; n8n platform uses PostgreSQL for n8n state; SigmaHelix OS uses a single SQLite file.

Mapping to your ops world

NeedPick
Local single-user app, no serverSQLite
Multi-user, concurrent writes, tenant isolationPostgreSQL
Transform/analyse a CSV in memoryPandas
Archive/export for analyticsParquet
