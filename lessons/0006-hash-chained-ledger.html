Lesson 0006 — Hash-chained audit ledger

Primary source: blockchain/Merkle-tree primer + Helix's audit_events design.

Why this lesson

A plain audit log can be edited after the fact and nobody notices. A hash-chained ledger makes tampering detectable: each entry's hash includes the previous entry's hash, so changing one record breaks every subsequent link.

Concept

  • Hash function: deterministic fingerprint of content (SHA-256). Same input → same hash; any change → different hash.
  • Chain: entry N stores hash(N-1). To verify, recompute each hash and check continuity.
  • Tamper evidence, not tamper proof: an attacker with write access can rewrite the chain, but cannot do it silently — the break is detectable by any independent verifier.
  • Append-only: entries are never edited or deleted; corrections are new entries referencing the old.

Helix writes every governance decision to the hash-chained audit_events ledger before execution, and ships an exportable governance evidence pack (Signoff builds the dossier from it).

Mapping to your ops world

Signed paper audit trail, sequential pagesEach page's hash includes the previous page
