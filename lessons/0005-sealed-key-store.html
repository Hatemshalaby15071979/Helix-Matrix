Lesson 0005 — Sealed key store

Primary source: OWASP Secrets Management Cheat Sheet; OS keyring docs.

Why this lesson

Cloud models need API keys; storing them in a file the project writes is a credential-exposure incident waiting to happen. A sealed key store keeps secrets in the OS keyring (or a vault), never in repo files, and never in logs.

Concept

  • OS keyring: the OS-provided secret store (libsecret/Keychain/Credential Manager). Keys live outside the project's filesystem.
  • Sealed: the key is encrypted at rest by the OS; the app requests it at runtime, never persists it.
  • Never in files the project writes: no .env committed, no config with secrets, no log line printing a key.
  • Rotation: keys can be revoked and replaced without code changes.

SigmaHelix OS stores cloud-model keys in the OS keyring, never in a file the project writes. RTA Command Center records a real credential-exposure incident and its remediation in SECURITY_DECISIONS.md — the lesson was learned the hard way.
